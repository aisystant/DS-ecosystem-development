# S1 «Собранность» — общее описание проектного режима

> Каноническая рамка: `DS-my-strategy/docs/personal-dev-program-architecture.md` §2а (проектный режим) и §2б (S0-S3, ось `cp.rhy`→`cp.wld`). Этот документ — операционная инструкция для наставника S1, не новое знание: при противоречии с каноном канон побеждает.

## Поворот от руководства к проекту

Раньше неделя практикума строилась вокруг раздела руководства «Системное саморазвитие»: изучил раздел → сделал домашнее задание. Теперь неделя строится вокруг хода по одному личному проекту участника; материал руководства подключается адресно, когда в проекте возникает конкретное затруднение. Руководство — библиотека метода, не последовательность страниц.

Единица прохождения — личный проект осознанного изменения стиля жизни (три типа: переход, поддержание, исследование — канон §2а). Три показателя считаются раздельно: прогресс проекта, ступень ученика, качество петли обучения «действие → обратная связь → коррекция». Проект может не удаться, а ступень вырасти — это честный результат.

## Недельная петля (повторяется недели 1-9)

Каждая неделя держится на одном и том же наборе из четырёх полей плюс метод недели. Персонализируются только поля, метод и общая тема — общие для всей группы (принцип §2а: доменные советы не генерируются).

| Поле | Смысл |
|---|---|
| **Цель недели** | что хочу продвинуть в проекте |
| **Рабочий продукт недели** | что конкретно появится и что можно предъявить |
| **Критерий готовности** | по какому наблюдаемому признаку пойму, что готово |
| **Свидетельство** | 1-3 строки факта, не оценки, записанные в конце слота |

Плюс: **метод недели** (что осваиваем на материале своего проекта) и **что принести на встречу** (для разбора хот-сит).

**Ритм недели для наставника:**

1. **День 1 (понедельник)** — сообщение в чат: метод недели + напоминание про слот времени.
2. **Дни 2-4** — наставник в чате/личке подтверждает или уточняет формулировки проектов и продуктов недели.
3. **Середина недели** — одна короткая точечная реакция каждому участнику по таблице статусов (вопрос или подсветка, не полный разбор).
4. **День 5-6** — напоминание: что принести на встречу.
5. **Встреча (конец недели)** — хот-сит разбор 3-4 формулировок вслух, метод следующей недели, задание, рефлексия.

## Пул методов недель 1-9

Порядок по умолчанию совпадает с последовательностью старых методичек `ss-lesson-01..09.md` (раздел-источник указан для деталей метода) — это не жёсткий порядок, а **пул с приоритетом по умолчанию**: если на разборе наставник видит другое реальное затруднение группы, метод следующей недели можно поставить раньше своей очереди.

| Неделя | Метод недели | Источник деталей |
|---|---|---|
| 1 | Выбор проекта, первый фрагмент IWE, слот времени | `00-kickoff/`, `ss-lesson-01.md` |
| 2 | Инвестирование и учёт времени, ежедневные слоты, итерации и инкременты, формулировка рабочего продукта | `02-week-02/`, `ss-lesson-02.md` |
| 3 | Ритуал входа в проект, защита внимания от отвлечений | `ss-lesson-03.md` |
| 4 | Проверка допущений, мотивов и ограничений на материале проекта | `ss-lesson-04.md` |
| 5 | Роль человека, роль ИИ, метод и рабочий продукт проекта | `ss-lesson-05.md` |
| 6 | Целевая система, окружение, границы, обратные связи проекта | `ss-lesson-06.md` |
| 7 | Взгляд на проект из ролей предпринимателя, инженера, менеджера | `ss-lesson-07.md` |
| 8 | Аудит связки «человек + ИИ»: экзоскелет или автопилот; Персона / Память / Контекст | `ss-lesson-08.md` |
| 9 | Якорный эпизод, отделение свидетельства от интерпретации, подготовка к защите | `ss-lesson-09.md` |

Методички `ss-lesson-0N.md` остаются источником полного содержания метода (упражнения, примеры, тайминги встречи); материалы папок `0N-week-0N/` — только проектный слой (как применить метод к своему проекту, что принести, критерии).

## Три показателя и данные для гейта

Наставник ведёт таблицу участников (статус проекта, ступень, риски). По итогам первых недель эти данные питают решение по формату (открытая карточка Ф6 РП-385) и пороги гейта база→продвинутый уровень (Ф8 РП-385) — сюда, а не в отдельный документ, стекаются недельные счётчики: доля согласованных проектов, доля показанных рабочих продуктов, доля участников с полным циклом действие→обратная связь→коррекция.

## Три зоны безопасности

Действует канон §2а без изменений: зелёная зона (безопасные изменения распорядка) — свободно; жёлтая (диагноз, лечение) — только выполнение плана специалиста; красная (зависимость, РПП, суицидальный риск, насилие) — проект не принимается, участника направляют к профильной помощи. Скрининг — короткий вопрос на входе, не дисклеймер.
